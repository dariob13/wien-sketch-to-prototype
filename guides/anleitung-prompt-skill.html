Stadt-Wien-Prototypen per Prompt in Doop bauen

Du beschreibst eine wien.gv.at-Seite in ein paar Sätzen. Claude baut sie in Doop aus den offiziellen Wiener-Melange-Komponenten von handbuch.wien.gv.at, als mobile und als Desktop-Ansicht. Diese Anleitung führt durch die einmalige Einrichtung und zeigt, wie du gute Prompts schreibst.

Hast du schon eine Skizze in Figma oder Doop? Dann ist der Sketch-Skill /wien-revamp das bessere Werkzeug. Dafür gibt es eine eigene Anleitung. Dieser Skill arbeitet nur mit Text und, wenn vorhanden, einer bestehenden wien.gv.at-Seite als Vorlage.

1. Was du brauchst

  • Claude Code im Terminal, in der Claude-Desktop-App oder in einer IDE wie VS Code.
  • Einen Doop-Account. Die Anmeldung geht unter doop.design.
  • Node.js ab Version 22.20 für die Installation mit dem Skills-CLI. Mit dem eigenständigen Installer reicht Node.js 18.
  • Python 3. Auf dem Mac ist es meist schon da. Claude sucht damit die offiziellen Icons und Illustrationen.

Ob Node.js und Python installiert sind, prüfst du im Terminal:

node --version
python3 --version

2. Doop-Account anlegen

  1. Öffne doop.design und melde dich an.
  2. Lege zum Testen einen leeren Canvas an. Der Skill erstellt später eigene Canvases mit dem Namen „Stadt Wien Entwurf - Thema“, du musst hier also nichts vorbereiten.

3. Skill installieren

Im Terminal, mit dem Skills-CLI von Vercel. Der Befehl installiert den Skill für Claude Code und Codex, ohne Rückfragen:

npx skills add dariob13/Doop-Prototyper --skill stadt-wien-doop-prototyper -g -a claude-code -a codex -y

Ohne die Optionen am Ende fragt das CLI nach, für welche Agents es installieren soll:

npx skills add dariob13/Doop-Prototyper --skill stadt-wien-doop-prototyper

Alternative ohne Skills-CLI. Dieser Installer kopiert den Skill nach ~/.claude/skills/ und ~/.agents/skills/:

npx github:dariob13/Doop-Prototyper

Mit --force ersetzt er eine ältere Kopie. Das brauchst du, wenn der Skill schon einmal installiert war.

4. Doop mit Claude verbinden (MCP)

Claude spricht über eine MCP-Verbindung mit Doop. Die richtest du einmal ein.

In Claude Code (Terminal)

claude mcp add --transport http doop https://doop.design/mcp
  1. Starte danach Claude Code mit claude und gib /mcp ein.
  2. Wähle doop und dann Authenticate.
  3. Der Browser öffnet sich. Melde dich bei Doop an und bestätige den Zugriff.
  4. Zurück in Claude zeigt /mcp bei doop den Status connected.

In der Claude-Desktop-App

Unter Einstellungen und Connectors einen eigenen Connector mit der Adresse https://doop.design/mcp hinzufügen und im Browser bestätigen.

In Cursor

In ~/.cursor/mcp.json eintragen und beim ersten Aufruf die Anmeldung im Browser bestätigen:

{
  "mcpServers": {
    "doop": { "type": "http", "url": "https://doop.design/mcp" }
  }
}

5. Prüfen, ob alles funktioniert

  1. Claude Code neu starten, damit der Skill geladen wird.
  2. /mcp eingeben: doop muss connected sein.
  3. Einen kleinen Testauftrag geben, zum Beispiel: „Baue mit stadt-wien-doop-prototyper eine Themenseite ‚Baden‘ nach https://www.wien.gv.at/freizeit/baden“.
  4. Nach einigen Minuten nennt Claude den Link zum neuen Doop-Canvas.

6. Einen guten Prompt schreiben

Je genauer der Auftrag, desto weniger muss Claude raten. Nenne den Skill beim Namen oder rufe ihn mit /stadt-wien-doop-prototyper auf, und gib diese Angaben mit:

AngabeBeispiel
Thema der SeiteFahrradwerkstätte, Kindergarten-Anmeldung, Bezirksseite
Bestehende Seite als Quelle, falls es eine gibthttps://www.wien.gv.at/verkehr/radfahren/
Abschnitte, die du sicher willstBühne mit Bild, Quicklinks, Kontakt am Ende
Eigene TexteÜberschrift, Einleitung, Kontaktdaten
Ziel-Canvas, falls schon vorhandenLink zum Doop-Canvas

Ein vollständiges Beispiel:

Nutze stadt-wien-doop-prototyper und baue einen Doop-Prototyp
der Fahrradwerkstätte-Seite. Inhaltsquelle:
https://www.wien.gv.at/verkehr/radfahren/
Oben eine Bühne mit Bild, danach Quicklinks zu den Werkstätten
und am Ende ein Kontaktblock.

Willst du nur einen Plan ohne Bau, schreib „nur Blueprint“ oder „nur Plan“. Dann liefert Claude eine Abschnittsliste mit den passenden Patterns, legt aber nichts in Doop an.

7. Was Claude baut

  • Einen Canvas „Stadt Wien Entwurf - Thema“, oder deinen Canvas, wenn du einen genannt hast.
  • Auf der Seite „Referenz“ einen Import der Live-Seite zum Vergleichen. Dieser Import ist eingefroren: Doop entfernt dabei die Skripte, deshalb sehen Karten dort flach aus und Tabellen fehlen. Er dient nur zum Vergleich.
  • Auf der Seite „Prototyp“ zwei Frames: „Mobil“ mit 375 Pixel und „Desktop“ mit 1440 Pixel Breite. Beide nutzen dasselbe HTML aus den Handbuch-Patterns mit dem echten Theme.
  • Eine Zusammenfassung mit den verwendeten Patterns, der Theme-Version und den offenen Punkten.

8. Regeln, an die sich der Skill hält

  • Jeder Bereich stammt aus einem Beispiel auf handbuch.wien.gv.at. Header, Bühne, Karten und Footer werden nicht nachgezeichnet.
  • Texte kommen von der Live-Seite oder aus deinem Prompt. Adressen, Preise, Telefonnummern und Öffnungszeiten erfindet Claude nicht, sondern lässt einen Platzhalter wie [Telefonnummer prüfen].
  • Icons kommen nur von der Handbuch-Seite Icons, Illustrationen nur von der Seite Illustrationen. Für jede verwendete Illustration braucht es eine Freigabe vom Handbuch-Team. Claude listet sie deshalb als offenen Punkt.
  • Fotos ohne Freigabe werden zu grauen Platzhaltern. Stockfotos und KI-Bilder kommen nicht vor.

9. Ergebnis prüfen und weiterarbeiten

  1. Öffne den Canvas und vergleiche „Prototyp“ mit „Referenz“.
  2. Klicke in Doop direkt auf ein Element und hinterlasse einen Kommentar. Claude kann Kommentare lesen und umsetzen.
  3. Für Änderungen schreibst du Claude einfach, was anders sein soll, zum Beispiel „Ersetze die Quicklinks durch drei Karten mit Bild“.
  4. Frühere Stände eines Frames liegen in Doops Versionsverlauf.

Tastaturbedienung und Screenreader lassen sich in Doop nicht nachweisen. Das bleibt eine Prüfung für die Entwicklung.
